# 科学論文執筆のためのMarkdownガイド v.1.5.7

## 要旨

科学論文の執筆にMarkdownを使用する最大の利点は、視覚的なフォーマット（レイアウト）に気を取られることなく、文章の論理構造とコンテンツそのものに集中できることです。

MD//WORKS v1.5.7は、脚注、上付き文字、下付き文字、基本的な表、コードブロック、アウトライン表示、目次（TOC）の自動生成など、学術論文の執筆に不可欠な機能をサポートしています。これらのツールを組み合わせることで、研究ノート、技術レポート、会議資料、論文の草稿をプレーンテキストで効率的に作成できます。

まずは見出しを使って文書のアウトラインを作成し、脚注には一時的なテキストラベルを使用することをお勧めします。アイデアと科学的なストーリーを整理することを最優先し、最終的なレイアウトの調整は、コンテンツと構造が固まった後に行うのが効果的です。

## はじめに

論文やレポートを執筆している最中に、図がずれてしまったり、脚注の番号を手動で振り直したり、段落のフォーマットが予期せず崩れたりして、貴重な時間を無駄にした経験はありませんか？ これらの作業は、科学的な考察そのものとはほとんど関係がありません。

Microsoft Wordのようなワープロソフトは、WYSIWYG（What You See Is What You Get：見たままが得られる）での編集や、最終的な提出・印刷用ドキュメントの作成には非常に優れています。しかし、草稿段階での頻繁なマウス操作やレイアウト調整は、思考の連続性を妨げる原因になります。

Markdownの核となる哲学は、以下の2つの作業を明確に分離することです：

* **コンテンツの執筆と文書の構造化**
* **最終的な視覚レイアウトの調整**

執筆中は、シンプルな記号を使って見出し、強調、脚注、表、コードを指定します。視覚的な表示は、その後のレンダリングエンジンが処理します。

> **Version note:** This guide describes features planned for MD//WORKS v1.5.7. The current stable release is v1.5.6. Footnote support will become available with the release of v1.5.7.

## なぜ科学文書にMarkdownを使用するのか？

### 1. 執筆のフローを維持できる

テキストを強調したり脚注を挿入したりするために、複雑なメニューを操作する必要はありません。キーボードから手を離すことなく、わずかなキーストロークで文書の構造を記録できます。

### 2. 脚注の自動番号付け

段落の途中に新しい脚注を挿入したり、セクション全体を並べ替えたりしても、脚注番号は本文中の出現順序に従って自動的に再割り当てされます。

### 3. 科学的思考に集中できる

執筆中のレイアウト調整を最小限に抑えることで、実験データの解釈、論理的な議論の構築、考察の推敲に、より多くの注意を向けることができます。

Markdownは、必ずしも最終的な編集ツールの代わりになるわけではありません。最も効果的なワークフローは、まずMarkdownでコンテンツと構造を作り上げ、完成した文書をWord、PDF、HTML、LaTeXなど、指定されたフォーマットに変換・エクスポートすることです。

## 1. 引用と注釈の管理

科学・技術文書では、引用した文献と自分自身の補足説明を区別することが重要です。Markdownでは、この目的のために「引用ブロック（Blockquotes）」と「脚注（Footnotes）」が用意されています。

### 1-1. 引用ブロック

外部の文献や発言を引用するには、行頭に `>` を入力します。

**入力例:**

```markdown
> Markdownは、文書の構造と視覚的なフォーマットを分離します。

```

複数段落にわたる引用の場合は、引用する各行の先頭に `>` を追加します。

```markdown
> Markdownは、文書の構造と視覚的なフォーマットを分離します。
>
> このアプローチにより、著者はコンテンツと論理構造に集中できます。

```

引用元は、引用ブロックの直後、または脚注に記載する必要があります。

### 1-2. 脚注

脚注を使用すると、引用元、補足説明、執筆用のメモなどを本文の流れから切り離して記述できます。

本文中で脚注を参照するには、次のように記述します：

```markdown
特定の転写因子が、細胞の初期化プロセスにおいて極めて重要であることが報告されています。[^takahashi2006]

```

その後、脚注の内容を定義します：

```markdown
[^takahashi2006]: Takahashi K, Yamanaka S. Cell. 2006.

```

### 脚注定義の柔軟な配置

`[^label]: ...` のような脚注の定義は、Markdown文書内のどこにでも配置できます（参照されている段落の直下に置くことも可能です）。
文書をプレビューまたはエクスポートすると、すべての脚注定義が収集され、文書の末尾に番号付きの脚注リストとして表示されます。

### 1-3. 番号の代わりにテキストラベルを使用する

脚注のラベルは数字である必要はありません。執筆中は意味のある単語や文字を使用できます。

```markdown
新規のスクリーニング手法により、候補化合物を効率的に選択できるようになりました。[^screening_method]

ここにはさらなる考察が必要です。[^memo]

[^screening_method]: ここに詳細なスクリーニングプロトコルを記述する。
[^memo]: 後で追加の考察や参考文献を追記する。

```

プレビュー時には、`screening_method` や `memo` のようなラベルは、本文中の出現順序に従って 1、2、3... といった連番に自動変換されます。
これにより、すべての脚注番号を手動で振り直すことなく、段落を自由に並べ替えることができます。

> **注:** MD//WORKSは脚注に自動で番号を振りますが、完全な文献管理システムではありません。CSLフォーマット、BibTeXとの同期、またはジャーナル固有の自動引用スタイルが必要なワークフローの場合は、Zotero、BibTeX、Pandocなどのツールと併用することを検討してください。

## 2. 画像とリンクの挿入

図、グラフ、データセット、外部リファレンスは、多くの科学技術文書において不可欠な要素です。

### 2-1. 画像と図

実験グラフ、ダイアグラム、チャートなどの画像を挿入するには、感嘆符（`!`）、角括弧（`[]`）内の代替テキスト、丸括弧（`()`）内の画像パスを使用します。

```markdown
![処理48時間後の細胞生存率を示すグラフ](./images/fig1_survival_rate.png)

```

角括弧内のテキストは「代替テキスト（Alt text）」です。画像が表示できない場合に画像の内容を説明する役割を果たし、アクセシビリティの向上にも役立ちます。

Markdown自体には、標準化された図のキャプション（説明文）の構文はありません。簡単なキャプションであれば、画像の直下に通常のテキストとして記述できます。

```markdown
![処理48時間後の細胞生存率を示すグラフ](./images/fig1_survival_rate.png)

**図1.** 処理48時間後の細胞生存率。

```

### 2-2. ハイパーリンク

外部のデータセット、オンラインツール、または参考文献のソースにリンクするには、表示するテキストを角括弧で囲み、URLを丸括弧で囲みます。

```markdown
生データは[NCBI GEO](https://www.ncbi.nlm.nih.gov/geo/)から入手可能です。

```

## 3. 科学記号と化学記号

生命科学や化学の分野では、化学式、イオン電荷、単位、指数、統計的表記において、下付き文字や上付き文字が頻繁に必要になります。

### 3-1. 下付き文字

下付き文字として表示するテキストをチルダ（`~`）で囲みます。

**入力:**

```markdown
H~2~O, CO~2~, A~260~/A~280~

```

**出力:**
H₂O, CO₂, A₂₆₀/A₂₈₀

### 3-2. 上付き文字

上付き文字として表示するテキストをキャレット（`^`）で囲みます。

**入力:**

```markdown
Ca^2+^, 10^6^ cells, cm^2^, p < 0.05^*^

```

**出力:**
Ca²⁺, 10⁶ cells, cm², p < 0.05*

上付き・下付き文字の表記は、比較的短い表現に最適です。複雑な数式の場合は、専用のLaTeXレンダリングシステムが必要になる場合があります。

## 4. テキストの強調

科学論文では、遺伝子名、種名、重要な発見、ファイル名、関数、変数などを視覚的に区別することがよく求められます。

### 4-1. イタリック体（斜体）

テキストを単一のアスタリスク（`*`）で囲みます。

```markdown
*Escherichia coli*, *TP53*

```

イタリック体は、生物の種名に一般的に使用されます。遺伝子やタンパク質の名称に関するフォーマットの規則は、分野やジャーナルによって異なるため、必ず該当する執筆ガイドラインを確認してください。

### 4-2. ボールド体（太字）

テキストを二重のアスタリスク（``）で囲みます。

```markdown
**重要な知見**

```

太字は、重要な発見や警告を強調するのに役立ちますが、多用しすぎると可読性が低下する可能性があります。

### 4-3. インラインコード

ファイル名、関数、コマンド、または変数を単一のバッククォート（```）で囲みます。

```markdown
解析は `main.py` を使用して実行し、結果は `print()` 関数で出力しました。

```

## 5. 基本的なデータテーブルの作成

Markdownの表は、実験条件の比較や分析結果の要約に便利です。

```markdown
| 実験群 | 濃度 (µM) | 細胞生存率 (%) | 有意差 |
| :--- | ---: | ---: | :---: |
| コントロール | 0.0 | 100.0 | — |
| 処理 A | 10.5 | 82.4 | N.S. |
| 処理 B | 50.0 | 45.1 | **\*** |

```

### 配置（アライメント）の制御

区切り行にコロン（`:`）を使用することで、列の配置を制御できます：

* `:---` — 左揃え
* `---:` — 右揃え
* `:---:` — 中央揃え

数値データは通常「右揃え」にすることで、小数点以下の違いや桁数の比較がしやすくなります。

MD//WORKS v1.5.7は、標準的なMarkdownテーブルをサポートしています。セルの結合、複数行のヘッダー、表のキャプション、表専用の脚注、詳細な列幅の制御といったより高度な機能については、将来のバージョンで検討されています。

## 6. 技術文書用のコードブロック

研究にRNA-Seqパイプライン、統計スクリプト、画像解析、その他の計算ワークフローが含まれる場合、関連するコードをMarkdown内に直接記述できます。

複数行にわたるコードを3つのバッククォート（`````）で囲み、開始のバッククォートの後にプログラミング言語を指定すると、シンタックスハイライト（構文の強調表示）が有効になります。

```markdown
```python
import pandas as pd

data = pd.read_csv("cell_data.csv")
mean_survival = data["survival_rate"].mean()

print(f"Mean survival: {mean_survival}%")
```

```

よく使われる言語の識別子には以下のようなものがあります：

```text
python, r, bash, javascript, html, css, json

```

言語識別子を指定することで、キーワード、文字列、数値、コメントが視覚的に区別しやすいスタイルで表示されます。

コードを記述する際の注意点：

* パスワードやAPIキーを含めないでください。
* 機密データや個人を特定できるデータを含めないでください。
* 使用したソフトウェアとライブラリのバージョンを記録してください。
* 再現性が必要な場合は、重要な処理条件とランダムシードを含めてください。
* 非常に長いプログラムは別のソースファイルに保存し、文書には最も関連性の高い部分のみを含めるようにしてください。

## 7. 数式

MD//WORKS v1.5.7では、上付き文字と下付き文字を使用した基本的な科学表記をサポートしています。

```markdown
E = mc^2^
H~2~O

```

`$...$` を使用したインライン数式や、`$$...$$` を使用したディスプレイ数式など、ネイティブなLaTeX数式のレンダリングについては、v1.5.8以降のリリースで検討されています。

LaTeX表記の例は以下の通りです：

```markdown
$$
f(x) = \frac{1}{\sqrt{2\pi\sigma^2}} \exp\left( -\frac{(x-\mu)^2}{2\sigma^2} \right)
$$

```

MD//WORKS v1.5.7の時点では、この構文はフォーマットされた数式としてはレンダリング（描画）されません。

現時点で複雑な数式が必要な場合は、以下の方法を検討してください：

* 数式を画像として挿入する。
* 最終的なファイル変換にPandocを使用する。
* 専用のLaTeX環境を使用する。
* 数式レンダリングがサポートされる将来のバージョンを待つ。

## 8. 執筆ワークフローの例

1. **骨組みを作る**
まずは `# 概要（Abstract）`、`## 手法（Methods）`、`## 結果（Results）` など、大見出しのみを記述します。
2. **要点を箇条書きにする**
各見出しの下に箇条書きを追加し、意図した論理展開を構築します。
3. **要点を文章に膨らませる**
最終的なフォーマットを気にすることなく、箇条書きを完全な文章に変換していきます。
4. **一時的な脚注ラベルを使用する**
思考を途切れさせずに執筆を続けるために、`[^find_paper_later]`（後で論文を探す）のような一時的なラベルを追加します。
5. **文書構造を見直す**
アウトライン表示と自動生成された目次（TOC）を利用して、階層構造と論理的な順序を確認します。
6. **最終出力を準備する**
完成したMarkdown文書を、提出、出版、または配布に必要なフォーマットに変換・エクスポートします。

## 10. おわりに

科学・技術文書の執筆にMarkdownを使用する最大のメリットは、著者がフォーマットやレイアウトの調整に何度も邪魔されることなく、論理構造と科学的なコンテンツの執筆に集中できる点にあります。

MD//WORKS v1.5.7は、脚注、上付き・下付き文字、基本テーブル、コード表示、文書アウトライン、自動TOC生成など、実用的なサポートを提供します。
これらの機能を組み合わせることで、研究ノート、技術レポート、会議資料、初期の原稿を準備するための軽量な環境が実現します。

まずは見出しを使って文書の構造を構築し、脚注には意味のある一時ラベルを活用して、科学的なストーリーを優先しましょう。最終的な見た目の美しさは、内容が完成した後にいくらでも洗練させることができます。
