#  Guide to Markdown for Scientific Writing

## 要旨

科学論文の執筆にMarkdownを使用する大きな利点は、最終的なレイアウトに気を取られすぎることなく、文章の論理構造と科学的な内容に集中できることです。

Markdown自体は簡潔な文書記法ですが、多くのMarkdownエディタや変換ツールは、拡張機能として脚注、数式、表、コードブロックなどをサポートしています。Pandocなどの変換ツールと組み合わせることで、研究ノート、技術レポート、学会資料、論文草稿などをプレーンテキストで作成し、Word、PDF、HTML、LaTeXなどの形式へ変換できます。

効果的な執筆方法は、最初に見出しを使って文書の骨組みを作り、研究の目的、結果、解釈の順序を整理することです。内容と論理構造が固まった後で、投稿規定に沿った書式や最終レイアウトを整えます。

> **重要:** 脚注、表、数式、上付き文字、下付き文字などの一部の機能は、標準Markdownの共通仕様ではなく、エディタや変換ツールが提供する拡張構文です。同じMarkdown文書でも、使用する環境によって表示結果が異なる場合があります。

## はじめに

論文やレポートの執筆中に、図の位置がずれたり、脚注番号を振り直したり、段落の書式が予期せず変わったりして、時間を取られた経験はないでしょうか。こうした作業の多くは、実験結果の解釈や科学的な議論の構築とは直接関係しません。

Microsoft Wordのようなワープロソフトは、画面上で完成形に近い状態を確認しながら編集でき、最終的な提出文書を作成する用途に優れています。一方、草稿段階で頻繁にレイアウトを調整したり、マウスで書式を変更したりすると、執筆の流れが中断されることがあります。

Markdownを利用した執筆では、次の2つの作業をできるだけ分離します。

* **内容を執筆し、文書の論理構造を作る**
* **最終的な表示形式やレイアウトを整える**

執筆中は、簡単な記号を使って見出し、強調、引用、脚注、表、コードなどを記述します。画面上の表示や出力時のレイアウトは、エディタのプレビュー機能やPandocなどの変換ツールが処理します。

## なぜ科学文書にMarkdownを使用するのか

### 1. 執筆の流れを維持しやすい

見出しの追加、用語の強調、脚注の挿入などを、複雑なメニュー操作なしで記述できます。キーボードから手を離す機会が少なくなるため、文章の流れを保ちながら執筆できます。

### 2. 脚注番号を自動的に管理できる

脚注対応のMarkdown環境では、段落の途中に新しい脚注を追加したり、セクションを並べ替えたりしても、通常は本文中の出現順序に従って脚注番号が再生成されます。

ただし、脚注機能はすべてのMarkdown環境で共通して利用できるわけではありません。使用するエディタや変換ツールが脚注構文をサポートしているか確認する必要があります。

### 3. 科学的な内容に集中しやすい

執筆中のレイアウト調整を最小限に抑えることで、次のような本質的な作業に注意を向けやすくなります。

* 実験データの解釈
* 仮説と結果の対応関係の確認
* 論理的な議論の構築
* 限界や代替解釈の検討
* 考察の推敲

Markdownは、必ずしもWordやLaTeXなどの最終編集環境を置き換えるものではありません。実用的なワークフローの一つは、まずMarkdownで内容と構造を作り、完成した原稿を投稿先が指定するWord、PDF、HTML、LaTeXなどの形式へ変換する方法です。

プレーンテキストで保存されるため、Gitなどのバージョン管理システムを利用した変更履歴の確認にも適しています。

## 1. 引用と注釈の管理

科学・技術文書では、外部資料からの引用、参考文献の情報、著者自身による補足説明を区別することが重要です。

Markdownでは、引用文を示すために「引用ブロック」を、補足情報を本文から分離するために「脚注」を利用できます。ただし、引用ブロックそのものには、著者名、論文名、DOIなどの文献情報を管理する機能はありません。

### 1-1. 引用ブロック

外部の文献や発言を引用文として表示するには、行頭に `>` を入力します。

入力例：

```markdown
> Markdownは、文書の構造と視覚的なレイアウトを分離しやすい記法です。
```

表示例：

> Markdownは、文書の構造と視覚的なレイアウトを分離しやすい記法です。

複数段落からなる引用では、引用する各段落または各行の先頭に `>` を付けます。

```markdown
> Markdownは、文書の構造と視覚的なレイアウトを分離しやすい記法です。
>
> この方法により、著者は内容と論理構造に集中しやすくなります。
```

引用ブロックは、文章を引用として表示するための構文です。学術的な引用として使用する場合は、引用ブロックの直後、脚注、または参考文献リストに出典を明記してください。

原文をそのまま引用する場合は、引用部分を明確にし、必要に応じてページ番号や節番号も示します。文章を要約または言い換えた場合も、元となった文献の明示が必要です。

### 1-2. 脚注

脚注対応のMarkdown環境では、参考情報、補足説明、執筆中のメモなどを、本文の流れから分離して記述できます。

本文中で脚注を参照する例：

```markdown
特定の転写因子を導入することで、体細胞から多能性をもつ細胞を誘導できることが報告されています。[^takahashi2006]
```

脚注の定義：

```markdown
[^takahashi2006]: Takahashi K, Yamanaka S. Cell. 2006.
```

多くの脚注対応環境では、`[^label]` が本文中の参照位置を表し、`[^label]:` が脚注本文の定義を表します。

### 1-3. 脚注定義の配置

多くのMarkdown拡張では、脚注の定義を参照箇所の直後または文書の末尾に配置できます。レンダリング時には脚注が収集され、番号付きの一覧として出力されます。

ただし、脚注定義を置ける位置や、複数段落からなる脚注の記述方法は、Markdown処理系によって異なる場合があります。別のエディタや変換ツールへ文書を移す場合は、表示結果を確認してください。

### 1-4. 番号の代わりに意味のあるラベルを使う

脚注のラベルは、数字である必要はありません。執筆中は、内容を識別しやすい名前を使用できます。

```markdown
新しいスクリーニング法により、候補化合物を効率的に選択できました。[^screening_method]

この結果については追加の考察が必要です。[^discussion_memo]

[^screening_method]: スクリーニング条件と選択基準を追記する。
[^discussion_memo]: 関連する先行研究を確認し、考察に追加する。
```

脚注対応の処理系では、`screening_method` や `discussion_memo` などのラベルが、そのまま脚注番号として表示されるのではなく、通常は本文中の出現順序に従って1、2、3……のような番号に変換されます。

> **注:** Markdownの脚注機能は、完全な参考文献管理システムではありません。引用スタイルの切り替え、DOI情報の管理、参考文献リストの自動生成、BibTeXやCSLとの連携が必要な場合は、Zotero、Pandoc、BibTeXなどの利用を検討してください。

## 2. 画像とリンクの挿入

### 2-1. 画像と図

実験グラフ、顕微鏡画像、模式図、チャートなどを挿入するには、感嘆符 `!`、角括弧 `[]`、丸括弧 `()` を使用します。

```markdown
![処理48時間後の細胞生存率を示すグラフ](./images/fig1_survival_rate.png)
```

角括弧内の文章は「代替テキスト（alt text）」です。画像を表示できない環境やスクリーンリーダーを利用する環境で、画像が伝える情報を説明する役割があります。

代替テキストには、単に「グラフ」や「図1」と書くのではなく、画像が示す内容を簡潔に記述します。

Markdownの画像構文は、通常、画像ファイルへの参照を記録するものです。画像ファイルそのものがMarkdown文書内に埋め込まれるとは限りません。そのため、文書を移動または共有する際は、画像ファイルとフォルダ構成も一緒に管理する必要があります。

標準的なMarkdown構文だけでは、図番号、正式なキャプション、図表一覧、本文からの相互参照を十分に管理できません。これらが必要な場合は、Pandocの拡張機能、LaTeX、Quartoなどの利用を検討します。

### 2-2. ハイパーリンク

外部データベース、公開データセット、オンラインツール、参考資料などへのリンクは、表示する文章を角括弧で囲み、URLを丸括弧内に記述します。

```markdown
生データは[NCBI Gene Expression Omnibus](https://www.ncbi.nlm.nih.gov/geo/)から入手できます。
```

リンク先がデータセットや解析コードの場合は、URLだけでなく、アクセッション番号、バージョン、参照日なども必要に応じて記録します。

## 3. 科学記号と化学記号

生命科学、医学、化学、物理学の文書では、化学式、電荷、単位、指数などに上付き文字や下付き文字が必要になります。

ただし、上付き文字と下付き文字の記法は標準Markdownの共通機能ではありません。以下は、Pandoc Markdownなどで採用されている代表的な拡張構文です。

### 3-1. 下付き文字

下付き文字として表示する部分を`<sub></sub>`で囲みます。

入力：
```markdown
H<sub>2</sub>O、CO<sub>2</sub>、A<sub>260</sub>/A<sub>280</sub>
```

出力例：
H<sub>2</sub>O、CO<sub>2</sub>、A<sub>260</sub>/A<sub>280</sub>


### 3-2. 上付き文字

上付き文字として表示する部分を`<sup>　</sup>`で囲みます。

入力：

```markdown
Ca<sup>2+</sup>, 10<sup>6</sup> cells, cm<sup>2</sup>

```

出力例：

Ca<sup>2+</sup>, 10<sup>6</sup> cells, cm<sup>2</sup>

単純な化学式や指数には上付き・下付き文字が便利ですが、分数、積分、行列、複雑な反応式などを記述する場合は、LaTeX形式の数式を利用する方が適しています。

また、上付き・下付き構文の解釈はエディタによって異なるため、他の環境へ出力する際は表示を確認してください。

## 4. テキストの強調

### 4-1. イタリック体

テキストを1個のアスタリスク `*` またはアンダースコア `_` で囲みます。

```markdown
*Escherichia coli*
```

表示例：

*Escherichia coli*

生物の学名では、属名と種小名をイタリック体で表記するのが一般的です。属名は先頭を大文字、種小名は小文字で記述します。

遺伝子記号の表記規則は生物種や学術分野によって異なります。例えば、遺伝子記号をイタリック体で表し、対応するタンパク質名を立体で表す規則が用いられることがありますが、すべての生物種に共通するわけではありません。投稿先の規定や分野別の命名規則を確認してください。

### 4-2. ボールド体

テキストを2個のアスタリスク `**` で囲みます。

```markdown
**重要な知見**
```

表示例：

**重要な知見**

太字は重要な語句を目立たせるために使用できますが、論文本文では過度な使用を避け、見出し構造や文章そのものによって重要性を示すことが基本です。

### 4-3. インラインコード

ファイル名、関数名、コマンド、変数名などを1個のバッククォート `` ` `` で囲みます。

```markdown
解析には `main.py` を使用しました。
```

表示例：

解析には `main.py` を使用しました。

インラインコードは、コンピューター上で入力する文字列と通常の文章を区別するのに適しています。

## 5. 基本的なデータ表の作成

Markdownの表は、実験条件の比較や結果の概要を簡潔に示す場合に便利です。

```markdown
| 実験群 | 濃度（µM） | 細胞生存率（%） | p値 | 判定 |
| --- | ---: | ---: | ---: | :---: |
| コントロール | 0.0 | 100.0 | — | — |
| 処理A | 10.5 | 82.4 | 0.083 | ns |
| 処理B | 50.0 | 45.1 | <0.001 | *** |
```

表示例：

| 実験群    | 濃度（µM） | 細胞生存率（%） |     p値 |  判定 |
| ------ | -----: | -------: | -----: | :-: |
| コントロール |    0.0 |    100.0 |      — |  —  |
| 処理A    |   10.5 |     82.4 |  0.083 |  ns |
| 処理B    |   50.0 |     45.1 | <0.001 | *** |

### 配置の制御

区切り行にコロン `:` を追加すると、列の配置を指定できます。

* `:---`：左揃え
* `---:`：右揃え
* `:---:`：中央揃え

数値は小数点の位置を比較しやすくするため、右揃えが適しています。

有意差をアスタリスクで表す場合は、表の注記に基準を明記します。

```markdown
ns：有意差なし、*：p < 0.05、**：p < 0.01、***：p < 0.001
```

ただし、アスタリスクだけで結果を示すよりも、可能な場合は正確なp値、効果量、信頼区間、使用した統計手法、比較対象を併記する方が、結果を適切に解釈しやすくなります。

標準的なMarkdown表は、セルの結合、複数行のセル、複雑な注釈には向いていません。複雑な表が必要な場合は、HTML、LaTeX、Pandocの拡張表などを利用します。

## 6. 技術文書用のコードブロック

研究に統計解析、画像解析、データ処理などが含まれる場合は、解析コードをMarkdown文書内に記録できます。

複数行のコードを3個のバッククォートで囲み、開始部分に言語名を指定します。

````markdown
```python
import pandas as pd

data = pd.read_csv("cell_data.csv")
mean_survival = data["survival_rate"].mean()

print(f"Mean survival: {mean_survival:.1f}%")
```
````

表示例：

```python
import pandas as pd

data = pd.read_csv("cell_data.csv")
mean_survival = data["survival_rate"].mean()

print(f"Mean survival: {mean_survival:.1f}%")
```

よく使用される言語識別子には、次のようなものがあります。

* `python`
* `r`
* `bash`
* `javascript`
* `json`
* `yaml`
* `latex`

言語名を指定すると、対応するエディタではシンタックスハイライトが適用されます。ただし、コードブロックを記載しただけではコードが自動実行されるわけではありません。

解析の再現性を高めるには、コードだけでなく、使用したソフトウェア、ライブラリのバージョン、入力データ、乱数シード、主要な解析条件なども記録します。

## 7. 数式

MathJax、KaTeX、PandocなどをサポートするMarkdown環境では、LaTeX記法を使って数式を表示できます。

数式記法も標準Markdownの共通機能ではありません。使用する環境が、どの区切り記号とLaTeXコマンドに対応しているか確認してください。

### インライン数式

文章中に数式を埋め込む場合は、一般に数式を1個のドル記号 `$` で囲みます。

```markdown
質量とエネルギーの等価性は $E = mc^2$ で表されます。
```

表示例：

質量とエネルギーの等価性は (E = mc^2) で表されます。

### ディスプレイ数式

数式を独立した行として表示する場合は、多くの環境で2個のドル記号 `$$` を使用します。

```latex
$$
f(x)
=
\frac{1}{\sqrt{2\pi\sigma^2}}
\exp\left(
-\frac{(x-\mu)^2}{2\sigma^2}
\right)
$$
```

これは、平均 (\mu)、分散 (\sigma^2) の正規分布の確率密度関数を表します。

投稿先によっては、数式番号、式への相互参照、使用可能なLaTeXコマンドなどに制限があります。最終原稿へ変換する際は、投稿規定と出力結果を確認してください。

## 8. 執筆ワークフローの例

### 1. 文書の骨組みを作る

最初に大見出しだけを記述します。

```markdown
# 論文タイトル

## 要旨

## はじめに

## 材料と方法

## 結果

## 考察

## 結論

## 参考文献
```

実際の章構成は、研究分野や投稿先の規定に合わせて変更します。

### 2. 各節の要点を箇条書きにする

各見出しの下に、記載すべき結果、根拠、解釈を箇条書きで整理します。

特に考察では、次の順序を意識すると論理を組み立てやすくなります。

1. 主要な結果
2. 結果から直接導ける解釈
3. 先行研究との一致点または相違点
4. 代替解釈
5. 研究上の限界
6. 今後の検討課題

### 3. 箇条書きを文章へ展開する

最終的なフォント、余白、図の位置などを気にせず、要点を完全な文章に展開します。

この段階では、「結果」と「解釈」を混同しないことが重要です。観察された事実は結果に、そこから導かれる意味や仮説は考察に記載します。

### 4. 一時的な脚注ラベルを使う

確認が必要な文献や追記すべき内容には、一時的な脚注ラベルを追加します。

```markdown
この現象は既報のシグナル伝達経路と関連する可能性があります。[^find_related_paper]

[^find_related_paper]: 関連する一次論文を検索し、根拠を確認する。
```

原稿完成前に、一時的なメモが残っていないことを確認します。

### 5. 引用情報を整理する

脚注だけで文献を管理するのか、Zotero、BibTeX、CSLなどの文献管理システムと連携するのかを決めます。

投稿用論文では、著者名、論文名、雑誌名、発行年、巻、号、ページまたは論文番号、DOIなどを確認します。可能な限り、総説だけでなく、主張の根拠となる一次論文を参照します。

### 6. 最終出力を準備する

完成したMarkdown文書を、Pandocなどを用いてWord、PDF、HTML、LaTeXなどへ変換します。

変換後は、次の項目を確認します。

* 見出し階層
* 脚注番号
* 参考文献
* 数式
* 図と表
* 画像ファイルへのパス
* 単位と記号
* 改ページ
* 投稿先指定の書式

Markdown原稿が正しくても、変換先のテンプレートや処理系によって表示が変わる可能性があるため、最終出力の目視確認は必要です。

## 付録：MD//WORKSの対応状況とバージョン情報

本ガイドで説明した基本的なMarkdownの執筆方法は、専用エディタであるMD//WORKSを利用することで、より手軽に実践できます。

### 現在の安定版：v1.5.6

MD//WORKS v1.5.6では、互換性の観点から次のMarkdownの標準仕様および一部の代表的な拡張構文については対応しています。

* 見出し
* 箇条書きと番号付きリスト
* 太字と斜体
* 上付き文字
* 下付き文字
* 引用ブロック
* リンクと画像
* インラインコード
* フェンスコードブロック
* 基本的なMarkdown表
* 文書内の見出しを利用した目次表示

一方、v1.5.6では、基本的なMarkdownの執筆方法との互換性の観点もあり、本ガイドで説明したすべての拡張構文のプレビューに対応するに至ってません。未対応の構文も、プレーンテキストとして記述・保存することはできますが、MD//WORKS上で期待どおりにレンダリングされない場合があります。科学論文でよく使われる構文については、次期バージョン以降での対応を予定または検討しています。

### 次期バージョン：v1.5.7

v1.5.7では、科学・技術文書の執筆を支援するため、次の機能への対応を予定しています。

* 脚注のプレビュー表示
* 脚注番号の自動生成
* 意味のあるテキストラベルを用いた脚注

これにより、参考情報を含む科学文書を、より自然に記述できるようになります。

### 更なる拡張候補

今後のバージョンでは、長文執筆を支援するDeep Editing Modeを含め、次のような拡張機能が検討されています。

* 長文全体の構造を確認しながら編集する機能
* LaTeX記法による数式レンダリング
* より高度な表の作成
* 図表キャプション
* 図表番号の自動生成
* 本文から図表や節を参照する相互参照
* BibTeXやCSLとの連携
* 文献引用と参考文献リストの管理

現在のv1.5.6では、まず見出しを使って文書の骨組みを作り、科学的な内容と論理構造を整理することを推奨します。脚注等を利用する予定がある場合は、互換性を考慮しながら、拡張構文をプレーンテキストとして記述しておくことがおすすめです。

## おわりに

科学・技術文書の執筆にMarkdownを使用する大きな利点は、著者がレイアウト調整に何度も中断されることなく、論理構造と科学的な内容に集中しやすくなることです。

適切なエディタ、文献管理ツール、変換ツールを組み合わせることで、研究ノートから論文草稿までを一貫して管理できる、軽量で柔軟な執筆環境を構築できます。

一方で、Markdownには複数の方言や拡張仕様があり、脚注、数式、表、上付き文字、下付き文字などの対応状況は環境によって異なります。使用するツールの仕様を確認し、最終出力を必ず点検することが重要です。

まずは見出しを使って文書の構造を作り、研究目的、方法、結果、考察の関係を整理してください。科学的なストーリーと根拠が明確になった後で、投稿規定に沿った書式や最終的な見た目を整えるのが、効率的な執筆手順です。
